# T11 · 三阶魔方双模型语音集成

- **目标**：将已有三阶魔方 duel 页面嵌入 EasyInput，作为默认隐藏、语音显式打开的子模块，并通过实时通话识别结果控制双盘。
- **语音行为**：说“打开魔方”显示模块并抑制模型把魔方误当成待启动应用；模块打开后说“同步重新打乱/打乱魔方”直接触发双盘页右上角同步按钮；说“一键完成七步/一起开始复原魔方”同时点击两侧各自的“一键完成七步”按钮。
- **现有能力复用**：魔方页面分别维护 Jev / DeepSeek 状态、密钥、日志和计时。打乱生成一份共享 20 步公式；复原仍由各模型选择其本盘经过验证的候选方案。
- **安全边界**：仅从 EasyInput 本机实时转写事件发出命令；宿主和双盘容器校验来源、窗口和随机会话 token；模型 Key 留在魔方自身的存储和 API 请求中，不经 EasyInput 语音链路转发。
- **凭据持久化增量**：Jev / DeepSeek Key 分别保存到 macOS Keychain；魔方页面打开后自动回填到对应 provider。仅当 Keychain 无值时迁移旧 localStorage 密钥，输入更新经受限桥自动写入 Keychain。
- **验收**：默认隐藏；显式打开后双盘显示；“打乱魔方”点击既有同步按钮；“一起开始复原魔方”同时启动两边七步流程；普通语句、外来窗口消息及模块隐藏时不触发动作。
- **故障复盘**：首版父页面验证 `hello.clientId` 时错误地要求它等于父页面自己的随机 ID；实际双盘发送的是它自己的 ID，因此父页面从未完成握手，所有后续语音命令都被忽略。两个子魔方只发送一次 ready，也可能早于 duel 页监听器而丢失。
- **修复**：父页面现在记录并回信给双盘提供的 peer ID；双盘重复 hello 直到收到 welcome；duel 主动 ping 两个子魔方重新上报 ready。Rust 同时抑制已识别的魔方操作话语，防止模型声称没有工具；双边复原通过各自按钮 click 启动。
- **导航容错**：实时转写有时将“嗯，打开魔方”与前后语句合并。前端导航与 Rust 回复抑制现按标点切分并去除口头填充词，只将完整目标命令识别为打开/关闭动作，避免两侧判定不一致。
- **状态**：代码与编译检查完成，真实双盘页面状态变化及模型复原仍待语音实机验收。

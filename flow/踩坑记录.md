## 2026-09-21 · 直播嵌入、旧热词断言与 RTC 退出竞争　[代码已修复]

- **现象 / 根因**：直播默认 X-Frame-Options DENY 阻止内嵌；旧驾驶舱测试未更新“优秀学员列表”热词；声网 join 与 leave 并发时，先 leave 不保证取消进行中的 join。
- **解决**：显式嵌入服务模式只允许 EasyInput 来源；修正既有热词测试预期；RTC 会话先关闭媒体、等待 join settled 后 leave，并按局部实例清理。新增 RTC 成功/失败竞争测试。
- **其他评审修复**：Token 从浏览器持久化剔除、观众链接只带公开频道信息、中文美颜数值按位解析。
- **验证边界**：未收到开发板心跳，保留实板验收项；源码早期需求文档已有过时内容，本次以代码为准。见 `docs/直播工作室与硬件语音集成.md`。

## 2026-09-08 · Playwright 在受限环境中启动本机 Chrome 立即退出　[已解决]

- **现象**：训练营驾驶舱截图脚本首次启动 Chrome 无头进程后立即收到 `SIGABRT`，Playwright 报浏览器上下文已关闭，清理进程时还出现 `kill EPERM`。
- **根因**：当前受限执行环境不允许完整启动和管理本机 Chrome 子进程，不是驾驶舱页面或截图脚本错误。
- **解决**：在用户授权的本机执行环境中复用同一脚本，14 个页面全部成功加载并生成 PNG。
- **教训 / 怎么避免**：本机浏览器自动化若在启动阶段直接退出，应先区分系统权限与页面错误；截图仍需保留 HTTP 状态、目标标题和最终图像尺寸三层验证。

## 2026-09-06 · 英语学习长句被扬声器回声截断　[已解决]

- **现象**：“说”模块中，Milo 的完整文字已显示，但较长语音只播开头便停止；日志中的例句为 “That sounds nice! … Do you sing with classmates?”。
- **根因**：普通 Milo 回复没有启用学习播报输入保护。开发板麦克风把扬声器开头回传给云端，云端在原语音队列尚未播完时开始新一轮 ASR；客户端收到 `input_audio_transcription.started` 后清空扬声器队列，造成中途断句。
- **解决**：Milo 的所有回复从文字/音频响应开始便暂停云端音频输入，等最后一帧实际发给开发板后再恢复；播放期间已经滞留的转写事件只记诊断并忽略，不再清空播放队列或驱动新回复。
- **教训 / 怎么避免**：云端 `response.done` 只表示生成结束，不表示硬件已经播放结束；全双工链路必须以本地扬声器队列排空作为恢复麦克风上行的边界。

## 2026-09-06 · 旧 bundle 与 tauri dev 双开导致版本报错和钥匙串混乱　[已解决]

- **现象**：重新运行 `npm run tauri:dev` 后仍提示“配置版本 6 高于当前支持的 5”，并感觉每次重启都要重新输入模型 Key。
- **根因**：后台仍有一个 10:31 启动的旧 bundle 实例，同时运行当前调试实例；旧实例只支持配置版本 5。另一个问题是原 `dev.sh` 先签旧二进制、再后台轮询补签新二进制，不能保证 Cargo 执行前已经使用稳定身份签名。
- **解决**：关闭精确确认的旧 bundle；新增 `codesign-dev-runner.sh`，由 Cargo runner 在执行前签名；`dev.sh` 检测旧 bundle 并设置 runner。四个 Keychain 项确认真实存在，未读取或输出密钥值。
- **教训 / 怎么避免**：Tauri 主窗口关闭时应用可能只隐藏而不退出，切换调试版本前要用 `Command+Q`；开发签名必须发生在二进制执行之前；密钥输入框重启后留空是安全设计，看到“已安全保存”无需重复输入。

## 2026-09-06 · 配置版本 6 被旧二进制按版本 5 拒绝　[已定位]

- **现象**：语音识别时报“配置版本 6 高于当前支持的 5，已进入保护模式”。
- **根因**：当前源码和配置文件都已是版本 6；报错中的支持上限 5 只能来自旧版运行实例或旧安装包。
- **解决**：完全退出旧实例后，从当前仓库根目录运行 `npm run tauri:dev`，让 Cargo 重新编译当前代码。不要直接删除或降级配置版本，因为版本 6 包含语音动作和麦当劳 MCP 等新字段。
- **教训 / 怎么避免**：升级配置结构后，必须确认用户操作的是新编译的原生窗口；浏览器里的 1420 页面、Dock 中旧安装包和当前 Tauri 调试窗口可能同时存在。

## 2026-09-06 · PPT 运行时字体探测需要显式模块路径　[已解决]

- **现象**：使用绑定的 Node 运行时生成 PPT 时，`resolvePresentationFont()` 报 `RUNTIME_NODE_MODULES is required`。
- **触发条件**：只设置了 `RUNTIME_NODE`、`SKILL_DIR` 和 `TMP_DIR`，没有传入工作区依赖目录。
- **根因**：演示文稿工具的字体探测通过运行时依赖目录加载字体清单，不会自动从 Node 可执行文件反推模块路径。
- **解决**：运行生成命令时显式设置 `RUNTIME_NODE_MODULES=/Users/macforai/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules`，随后结构、布局、导入和渲染检查全部通过。
- **教训 / 怎么避免**：创建或编辑 PPT 前先调用 workspace dependencies，并把 Node、Node modules、Python 路径作为同一组环境变量传给工具链。

## 2026-09-06 · MCP 促销价格与配送菜单口径不一致　[已确认边界]

- **现象**：手机端看到“东南亚风味椰香鸡扒堡组合”9.9 元，但当前 MCP 配送菜单返回 19.9 元，报价为 26.90 元。
- **根因**：手机活动价与 MCP 当前配送渠道的菜单/优惠口径不同；当前 MCP 返回的三个配送门店都没有 9.9 元目标。
- **解决**：MVP 继续验证“能否点餐并走到支付二维码”，使用当前 MCP 可售的脆薯饼 x1，实际创建 ¥16.30 未支付订单并打开二维码页面；材料中把 9.9 元列为渠道差异，不做价格等同假设。
- **教训 / 怎么避免**：演示和排障时同时记录渠道、门店、商品编码、菜单价、配送费、包装费和优惠券口径；不能只按商品名称比较价格。

## 2026-09-06 · 完整 Rust 测试中的本地监听用例受沙箱限制　[环境限制]

- **现象**：`cargo test` 的两个 socket 相关测试在当前受限执行环境返回 `Operation not permitted`。
- **根因**：测试需要绑定本地监听端口，执行沙箱禁止该系统调用；失败发生在测试启动阶段，不是断言失败。
- **解决**：单独运行不需要监听端口的麦当劳订单测试，10 项全部通过；前端构建和 13 项前端测试也通过。真实 macOS 开发环境应重新运行完整 Rust 测试。
- **教训 / 怎么避免**：把网络/端口测试与纯逻辑测试分开记录；在沙箱内不要把系统调用权限错误解读为业务回归。

## 2026-09-04 · Tauri 启动时端口 1420 被浏览器预览占用　[已解决]

- **现象**：`npm run tauri:dev` 的 `beforeDevCommand` 启动 Vite 失败，提示 `Port 1420 is already in use`。
- **根因**：此前为浏览器验收单独启动的 `npm run dev` 仍在监听 1420；Tauri 会再次通过 `beforeDevCommand` 启动同一服务。
- **解决**：停止此前的独立 Vite 会话，保留驾驶舱 3000 服务，再运行 `npm run tauri:dev`；Vite、Rust 编译和 EasyInput 调试进程均成功启动。
- **教训 / 怎么避免**：浏览器预览与 `tauri:dev` 不应各自启动一份 1420 服务；切换到原生联调前先停止独立 `npm run dev`。

## 2026-09-04 · Tauri 依赖默认不暴露 `tauri::test`　[已绕过]

- **现象**：尝试用 `tauri::test::mock_builder()` 做 Rust 侧事件往返测试时，依赖编译提示 `tauri::test` 被 feature gate 隐藏。
- **根因**：依赖 crate 不会继承当前 crate 的 `cfg(test)`，项目也没有为 Tauri 启用 `test` feature。
- **解决**：不为单项测试扩大依赖特性；保留参数/工具 Schema 的纯 Rust 测试、前端消息结构测试和两端完整编译，真实事件往返列入 Tauri 实板验收。
- **教训 / 怎么避免**：需要 Tauri mock runtime 时应在计划阶段确认 `tauri` 的 `test` feature 和锁文件影响，不能假设业务 crate 的 `cfg(test)` 会传递给依赖。

## 2026-09-04 · `cargo fmt` 的文件参数仍产生全 crate 格式化噪声　[已解决]

- **现象**：尝试只格式化 `realtime.rs` 时，多份与本任务无关、原本干净的 Rust 文件也被改写。
- **根因**：当前 `cargo fmt` 调用仍按 crate targets 运行，附加的文件参数没有把作用域限制为单文件。
- **解决**：根据变更前状态，将 10 份原本干净的无关文件恢复为原内容，并确认它们不再出现在 `git status`；后续只对目标文件使用补丁和编译检查。
- **教训 / 怎么避免**：脏工作区中不要依赖 `cargo fmt -- <file>` 隔离范围；先用 `cargo fmt --check`，确需单文件格式化时直接验证工具实际作用域并预存差异。

## 2026-09-04 · Vite 环境变量缺少 TypeScript 声明　[已解决]

- **现象**：新增 `import.meta.env.VITE_COCKPIT_URL` 后，测试通过但 `tsc` 报 `ImportMeta` 不存在 `env` 属性。
- **触发条件**：项目原先没有 `src/vite-env.d.ts`，TypeScript 未载入 Vite 客户端环境类型。
- **根因**：`vite.config.ts` 的 `envPrefix` 只控制变量暴露范围，不会自动为应用源码声明 `ImportMetaEnv`。
- **解决**：新增 `src/vite-env.d.ts` 并引用 `vite/client`，随后前端构建通过。
- **教训 / 怎么避免**：首次在 Vite 页面读取 `import.meta.env` 时，同时确认项目已包含 `vite/client` 类型声明；测试不一定会执行完整 `tsc`。

## 2026-09-04 · project-flow-cy 源模板缺少可执行位　[已绕过]

- **现象**：在 skill 源码目录运行 `bash tests/test-stop-hook.sh`，测试在行为断言前失败，提示模板 `assets/templates/.hooks/stop-doccheck.sh` 不可执行。
- **触发条件**：当前安装的 project-flow-cy skill 模板文件未携带执行权限。
- **根因**：skill 安装目录中的模板文件权限不是可执行，而测试会先用 `-x` 检查该模板。
- **解决**：不修改项目外的 skill 安装目录；将脚本内容接入本项目后，对项目副本执行 `chmod +x`，再针对项目副本运行等价行为回归。
- **教训 / 怎么避免**：接入时同时验证脚本内容与文件权限，不能只依赖模板源码测试的结果。

## 2026-09-28 · 魔方模型 Key 使用 macOS Keychain

- **决定**：Jev 与 DeepSeek API Key 分开写入 Keychain，通过 EasyInput 与本机魔方页面的来源/token 校验桥接按模型回填；输入后自动保存。旧 localStorage Key 仅在 Keychain 对应项为空时迁移。
- **原因**：集成页面 origin 会随 EasyInput 宿主变化，浏览器 localStorage 不适合作为桌面应用跨次启动的凭据持久层；项目既有约定要求敏感凭据进入 macOS Keychain。

## 2026-09-21 · T09 复用硬件采集和 ASR，隔离直播会话

- **确认依据**：用户确认 T09 的受控子页面与硬件识别方案。
- **决定 / 为什么**：保持 Vue 直播功能和独立观众端，宿主只提供受限字幕会话；普通硬件听写会注入文字，故不能直接把其完整生命周期复用给直播。字幕只消费专用 ASR 事件。
- **边界**：开发板仅作识别输入，RTC 音轨仍用电脑麦克风；语音密钥不出 Rust，RTC Token 仅在用户点击后写 Keychain。实现与验证指针：`docs/直播工作室与硬件语音集成.md`。

## 2026-09-06 · Tauri 开发二进制使用稳定的 Keychain 身份

- **背景**：打包应用的签名标识为 `pro.easyinput.desktop.intel`，Cargo 原始调试二进制此前以构建相关的临时标识运行；两者访问同一 Keychain service 时会出现重复授权或读取不一致。
- **决定**：只在 `npm run tauri:dev` 的开发链路中使用 Cargo runner，在每次执行前进行 ad-hoc 签名，并显式设置稳定 Identifier 与 designated requirement；正式构建仍沿用现有发布签名流程。开发脚本发现旧 bundle 运行时直接提示退出，不自动杀掉未知用户进程。
- **原因**：runner 能保证“先签名、后执行”，避免原后台轮询脚本在 Cargo 已启动二进制之后才补签；稳定 requirement 与开发 bundle 保持一致，减少 Keychain 反复授权。
- **安全边界**：该 ad-hoc 方案仅用于本机开发。生产发布仍必须使用 Developer ID 与公证，不把弱开发签名当作发布安全身份。

## 2026-09-06 · 演讲材料采用原生可编辑流程图并保留 MVP 边界

- **背景**：需要把麦当劳 MCP 语音点餐过程用于演讲，同时让后续维护者能继续编辑流程图和说明。
- **决定**：PPT 使用原生文本、形状和连线表达架构、9 步流程、状态和安全闸门；不把流程图导出成单张图片。内容明确区分“已创建真实未支付订单并展示二维码”和“未自动完成付款”。
- **原因**：原生对象便于演讲现场修改和后续迭代；显式保留边界可以避免把支付展示误解为代用户付款。
- **否决的方案与原因**：不把 9.9 元手机活动价当作 MCP 已验证价格，因为当前配送菜单返回的是另一价格口径。

## 2026-09-04 · 驾驶舱控制保持客户端内置工具，页面回执后才向模型报成功

- **背景**：开发板已提供实时通话触发和双向 PCM；驾驶舱模块选择属于页面业务，若下放固件会让固件与页面结构耦合。仅在 Rust 发出事件后立即返回成功，又无法确认 iframe 是否真正加载和切换。
- **决定**：在豆包实时会话中始终加入受限 Schema 的 `cockpit_navigate`；Rust 校验模块和期次后发出带一次性响应事件的 Tauri 请求，React 自动进入驾驶舱并转发，驾驶舱返回同一 `requestId` 后才将工具结果回传模型。
- **原因**：固件维持稳定音频协议，客户端统一管理意图、页面和安全边界；真实回执避免页面加载失败时向用户虚报成功。
- **安全边界**：工具模块为固定枚举，期次仅允许 1—7；iframe 结果同时校验 `event.source`、来源域名和 `requestId`；等待 12 秒超时后安全失败。
- **否决方案**：新增固件驾驶舱指令或只用前端广播事件“即发即成功”；前者形成跨项目强耦合，后者缺少执行真实性。

## 2026-09-04 · 复用驾驶舱页面并以有界模糊匹配处理语音

- **背景**：训练营驾驶舱与 EasyInput 分属两个现有项目；语音识别文本存在同音字、漏字和口语包装词，完全匹配会降低导航成功率。
- **决定**：EasyInput 通过受控 iframe/WebView 集成驾驶舱，不复制业务代码；语音侧使用标准化、常见 ASR 纠错、别名与编辑距离评分，并设置最低置信度和候选差距门槛。
- **原因**：保持驾驶舱唯一实现与独立发布能力，同时提高近似表达命中率；置信度与歧义门槛可以防止宽松匹配演变为误跳转。
- **安全边界**：页面消息同时校验父窗口来源和明确的来源白名单；Tauri CSP 仅允许本地驾驶舱与已发布驾驶舱域名。
- **否决方案**：将驾驶舱源码复制进 EasyInput，或对任意近似文本执行最高分候选；前者会形成两套真相源，后者会放大误操作风险。

## 2026-09-04 · 将 EasyInput 作为一个项目边界管理

- **背景**：仓库同时包含 React/TypeScript 界面与 Rust/Tauri 本地能力。
- **决定**：二者共享一套根级 `flow/`、`docs/` 和 hooks，不在 `src/` 与 `src-tauri/` 内重复建立控制面。
- **原因**：前后两层共享版本、IPC/event 契约、构建流程和最终发布物；仓库内只有一个 `.git`，没有独立发布或团队边界。
- **否决方案**：把 `src/` 和 `src-tauri/` 当作独立项目；这会重复计划与交接，并让跨层契约失去唯一入口。

## 2026-09-08 · 飞书原始快照与后续补充数据分开归档

- **背景**：驾驶舱的数据目录同时存在飞书抓取快照、页面展示契约以及用户后来补充的优秀学员明细；三者来源和证据等级不同。
- **决定**：把 `training_camp_summary.json` 作为本次飞书原始归档的唯一事实源，同时保存逐字节一致的 JSON 和人类可读 Markdown；页面契约、分析结论和用户后补的 45 位优秀学员不写入这份原始快照。
- **原因**：保持来源可追溯，避免把派生指标或人工补充数据误认为飞书当时已经抓取到的行级数据。
- **后续约束**：取得底层 Base 表权限后的行级导出应另建带抓取时间的新快照，不覆盖 2026-09-04 的历史归档。

## 2026-09-28 · 麦当劳语音播报只使用区县级地址标签

- **决定**：实时语音向用户播报已保存配送地址时，仅读区/县级标签和选项序号；不播报小区、街道、楼栋、房间号、联系人或手机号。完整地址仍由 Rust 本地订单会话保留并传给正式配送请求。
- **原因**：用户可通过序号和区县区分地址，同时避免语音外放详细住址隐私。

## 2026-09-28 · 实时通话增加唤醒词待命模式

- **背景**：用户希望暂不结束开发板实时语音通话时，让助手停止回答和软件控制，之后用指定口令恢复。
- **决定**：通话页提供每次启动时选择的“唤醒词待命”开关；开启后识别“闭嘴吧”“请你休息一下”等休息表达即进入静默待命，检测到“八弟八弟”及常见近音转写后恢复。待命只门控助手输出与工具动作，保持上行识别以接收唤醒词；触发词后的同轮内容继续作为用户任务处理。
- **原因**：会话保持连接即可免去重新握手与硬件启动；客户端 Rust 门控同时覆盖直接匹配动作、Function Calling 和模型普通回答。

## 2026-09-28 · 三阶魔方沿用独立双盘页面并受控接入语音

- **背景**：用户要求将已有 Jev / DeepSeek 双模型三阶魔方作为 EasyInput 隐藏模块，并以语音操作同步打乱和两边七步复原。
- **决定**：保留三阶魔方现有页面、独立模型配置与本机代理；由 EasyInput 本机启动 8787 服务，仅通过校验来源和随机 token 的消息桥发送固定的同步打乱/双模型复原命令。模块默认隐藏，识别到“打开魔方”后才显示。
- **原因**：不复制重写成熟的 3D 与求解流程，不让 EasyInput 接触模型 Key；固定命令桥把实时语音控制限制在用户明确请求的两项功能。

## 2026-09-28 · 通话中可切换唤醒待命并抑制关闭模块后的模型插话

- **背景**：实录确认问题会话以 `wakeWordEnabled=false` 启动，且语音设置在通话中被禁用；关闭驾驶舱由前端宿主完成，但同轮模型回复仍会播报“不支持关闭”。
- **决定**：将唤醒待命开关改为通话中也可切换，并由 Tauri 命令确认 Rust 会话状态更新；宿主直接关闭模块的转写在 Rust 侧标为已处理，取消模型文本、语音及同轮 Function Call。
- **原因**：通话期切换能即时进入/退出静默；由执行动作的客户端负责抑制同轮模型输出，避免成功的 UI 操作后又听到相反答案。

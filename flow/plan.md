## T09 直播软件整合（已确认方案）

- 功能依据：以外部项目当前 `src/App.vue`、`src/nama/` 的实现为准；早期需求文档中的染发和访谈状态不代表当前功能。
- 在 EasyInput 增加“直播工作室”，沿用受控 iframe 子系统方式承载 Vue 页面，保留摄像头预览、FaceUnity 美颜/贴纸、人脸跟随字幕、声网发布及观众入口。桌面嵌入模式的字幕和贴纸控制统一消费 EasyInput 实时对话的开发板用户最终转写，通过来源/token 校验的受限消息桥转发；视频字幕只显示用户语音，不接收模型回答。沿用外部项目源码，不整体改写成 React；本地服务启动、固定端口和故障提示纳入交付。
- 桌面嵌入直播不启动独立直播 ASR 会话；实时对话使用已有开发板 PCM → Rust 实时会话 → 豆包实时模型转写链路。字幕消费仅用户最终转写事件，贴纸命令消费同一事件；本地特效执行抑制模型同轮回答，不注入系统前台文字、不执行全局语音动作。
- 嵌入模式关闭浏览器识别和直播 Node ASR；独立网页保留原行为。宿主仅通过校验 origin/source/clientId/token 的协议传递用户转写与有限 RTC Keychain 操作，不暴露 Tauri 通用调用或 ASR 凭据。
- 本轮“复用硬件”的范围是语音识别输入；观众收听仍沿用原有 RTC 麦克风音轨，不自动将硬件 PCM 接入直播推流。摄像头、FaceUnity 授权、声网配置仍为现有外部依赖；RTC 敏感 Token 的桌面持久化需使用 Keychain。
- 验证：两项目构建和相关测试、桥接及 Rust 契约回归、Intel 构建/架构校验；在原生 WKWebView 验证摄像头、WebGL/WASM、canvas captureStream 和声网支持，在实板验证实时对话用户字幕、回答不入画及贴纸控制。若 WKWebView 不支持关键媒体能力，记录实测结果并提交架构调整方案。
- 任务卡：`flow/tasks/T09-live-studio-integration.md`。

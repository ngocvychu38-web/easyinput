# 英语学习子系统与实时语音集成

T05，用户于 2026-09-06 确认采用独立英语应用 + 内嵌页面 + 共享 EasyInput 实时语音的方案。

## 使用

1. 启动 `/Users/macforai/Documents/ChatGPT/英语学习` 的 `npm run dev -- --port 3000`。英语应用仍在自己的仓库开发；本轮没有发布在线版本。
2. 打开 EasyInput，进入主导航“英语学习”。入口默认 `http://localhost:3000/`，完整小岛、六单元活动、午餐冒险和教师页均保留。
3. 在 EasyInput 的语音服务配置中启用现有豆包实时语音并保存密钥，保持开发板与电脑的音频链路可用。英语学习不用再填写密钥。
4. 午餐冒险点击“开启陪伴”，或在六单元口语活动点击“开启实时语音”。真实输入和回复分别经开发板麦克风、扬声器传输；在学习活动中按开发板通话键可开启或暂停当前活动。
5. “等一下”打断；静音停止向云端发送麦克风帧；休息、结束、离开学习页会关闭本页拥有的会话。提示词更新沿用同一通会话。

浏览器里的 EasyInput 页面可以查看内嵌界面，但会明确拒绝开启原生语音。独立英语网页保留原有 Mock 体验和浏览器朗读。六单元听力、阅读的原有单句朗读仍由浏览器提供；本次替换的是交互式实时语音。

本地开发验收优先使用 `npm run tauri:build:debug:app` 生成的本机签名应用，避免 `tauri dev` 因改动 Rust 源码自动终止用户正在测试的会话。它不是正式 Developer ID 签名或公证发布包。

## 责任边界

- 英语应用管理教师提示词、场景、五项完成证据与本地进度。只处理最终转录；回声剥离后的空文本不传给学习页面，同一转录标识不重复处理。Milo 开始生成播报时，宿主暂停开发板麦克风上行，最后一帧发往开发板后再恢复；播放期间滞留的回声转写不得清空扬声器队列或生成新回复。
- EasyInput 管理 Keychain、官方服务域名校验、唯一实时会话、16 kHz 上行、24 kHz 下行以及开发板控制协议。学习会话固定正常语速，不覆盖用户保存的普通通话配置。
- 学习会话不加载驾驶舱、麦当劳或本机动作工具；即使服务端意外返回 Function Call，学习模式也不会执行。
- 模型回复不是学习完成证据。口语进度遵循原应用判定，午餐活动按不同物品计数；写作转录只能成为空白纸条的口述草稿，仍须用户修改并保存。
- 教师通用提示词用于全部学习会话，口语提示词用于六单元口语；午餐冒险使用通用 + 当前听/说/读/写提示词。超出 16,000 UTF-8 字节会显示错误，不能静默截断。
- 浏览器 localStorage 的键与内容保留。Safari、Chrome 与 Tauri 各有自己的存储容器，本次没有跨浏览器迁移数据；模型密钥不会进入这些存储。

## 消息与 IPC 契约

协议 `easyinput:learning:v1`：子页先发送带 `clientId` 的 `hello`，父页验证 iframe `contentWindow` 和精确来源后签发页面 token。子页只接受已知 EasyInput 来源的父窗口消息。

每个请求包含 `clientId`、`token`、UUID `requestId`、UUID `ownerId` 和有限的 `action`。宿主串行处理请求，对重复请求和旧页面 token 拒绝执行。刷新或导航更换 clientId 时关闭旧租约；启动期间离页时，迟到成功的会话也会停止。

| action | 行为 |
|---|---|
| start | `start_realtime_call({learning:{ownerId,instructions,greeting}})`；返回 sessionId |
| context | `learning_realtime_command` 更新 session instructions，等待 `session.updated` |
| text | 将文字作为 `conversation.item.create` 用户上下文；本地任务规则处理文字表达，使用当前任务引导回答 |
| speak | `speech_text_buffer.commit` 合成明确的任务提示、重听或文字反馈；不让模型猜测页面是否完成 |
| interrupt | 清空待播放音频，活动响应使用 `response.cancel` 并等待确认；空闲时直接成功 |
| mute / sound | 分别控制云端麦克风输入和开发板音频输出 |
| stop | 停止云端及开发板流；宿主等待原会话到终态后才确认，随后才能重连 |

`learning_realtime_command` 再校验 ownerId 和 sessionId，子页拿不到通用 Tauri invoke。宿主向子页仅转发本会话的状态和 `learning-transcript`（sessionId、id、role、text）；状态可以包含输入/输出包计数，但不含密钥。`RealtimeCallState.learningOwner` 是新增可选字段；终态保留 sessionId 便于订阅者匹配最后一次状态。

普通实时通话仍可不传 `learning` 参数。会话创建使用启动互斥锁；运行循环等宿主保存控制通道后才启动，避免极快断线留下已关闭 sender。

协议依据：[豆包实时语音 3.0 官方全双工接口](https://docs.volcengine.com/docs/6561/2549778?lang=zh)。本次核对了官方公开 `getDocDetail` 内容中的 session.update / session.updated、response.cancel / response.canceled、上下文管理和语音合成事件。

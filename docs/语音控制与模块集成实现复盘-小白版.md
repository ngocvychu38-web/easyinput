# EasyInput 语音控制与模块集成实现复盘（小白版）

**读者：** 刚接触桌面应用、实时语音和前端集成的开发者。本文根据 EasyInput 项目聊天需求、任务卡、实现说明和当前源码整理，重点解释业务路径、技术路径、踩坑原因与验收方法。

**阅读提示：** “代码已实现”表示仓库内有对应实现或自动验证记录；不等于真实开发板、在线模型、摄像头、FaceUnity、声网和外部服务已经全部完成端到端验收。验证状态以各任务卡和模块说明里的记录为准。

## 1. 先看全局：一句话怎样变成软件动作

EasyInput 是 Tauri 桌面应用。React 页面负责界面和模块容器，Rust 负责实时语音会话、动作判定、本地服务和受限 IPC。用户通过开发板说话后，语音事件进入 Rust；Rust 决定这句话是普通对话、唤醒/休息控制，还是某个明确的软件命令。允许执行的命令再通过窄接口送给对应页面，页面调用自己已有的按钮或业务函数，最后把执行结果反馈给宿主或语音会话。

```text
开发板麦克风 / PCM
        ↓
Rust 实时会话（ASR、对话、Function Calling、本地命令门控）
        ↓
受控的导航或页面消息桥
        ↓
驾驶舱 / 英语学习 / 直播 / 麦当劳 / 魔方
        ↓
执行结果与用户可见反馈
```

小白可以记住三条分工：**模型负责听懂意图，客户端负责权限和状态，页面负责执行既有业务。** 不要让模型直接拼任意 JavaScript，也不要把所有页面状态交给模型猜。

## 2. 语音软开关：休息但保持监听

### 2.1 业务目标

用户说“闭嘴吧”“请你休息一下”等休息表达后，希望助手停止回答，也不再替用户操作软件；但实时通话不结束，麦克风识别仍保持运行。用户之后说“八弟八弟”或 ASR 能识别出的近音（例如“巴迪巴迪”“巴蒂巴迪”），助手恢复工作。唤醒词后面紧跟任务时，例如“八弟八弟，打开驾驶舱”，恢复后应继续处理这条任务。

这里的“开关”是**对话/动作门控**，不是关闭麦克风、断开 PCM 或结束实时会话。否则没有持续识别，就听不到再次唤醒。

### 2.2 状态路径

```text
正常工作
  ├─ 休息表达 → 取消正在生成的回答 / 拦截新动作 → 静默待命
  └─ 开关关闭 → 按原始实时对话行为运行

静默待命
  ├─ 普通说话 → 识别但丢弃，不回答、不执行
  └─ “八弟八弟”及近音 → 恢复工作
       ├─ 只有唤醒词 → 等待下一句
       └─ 唤醒词 + 任务 → 同一轮继续执行任务
```

### 2.3 技术实现路径

开关状态由通话 UI 和 Rust 实时会话同步；会话处理中先做本地门控，再决定是否把该轮交给模型、Function Calling 或页面动作。休息表达还需要中止正在进行的模型输出，不能只阻止下一轮，否则助手仍会把当前回答说完。待命状态仍处理用户最终转写，仅让门控器识别唤醒词，普通内容直接丢弃。

ASR 不一定逐字输出用户说的唤醒词。项目曾遇到“八弟八弟”被识别成“巴蒂巴迪”，因此要把常见近音归一成同一唤醒意图。近音表应有限且可审查，避免把普通句子误判为唤醒。

### 2.4 踩坑与排查

最初用户报告“已经说休息，系统还是插话”，根因思路是只做 UI 状态或只挡住新请求，没有取消当轮输出/所有动作路径。另一类问题是“唤醒没反应”：实际会话启动时 `wakeWordEnabled=false`，且 ASR 输出为近音文本；只看开关界面或只匹配标准拼写都不足以定位。

排查顺序：检查会话是否真的收到启用状态；检查最终转写原文和归一化文本；确认休息分支是否中止当前回答；检查静默时 Function Calling 和本地页面命令是否都被挡住；最后用“唤醒词单独说”和“唤醒词 + 任务”分别验收。真实开发板端到端仍需实测。

## 3. 默认隐藏模块：通过语音打开与关闭

驾驶舱、英语学习、麦当劳点餐、直播和魔方等子模块默认不占据主界面或导航入口，语音明确提出“打开……”时再显示。这样能让桌面主界面保持简单，同时允许免手操作。

语音命令不等于页面已打开。导航分为两步：先由宿主识别目标模块并切换页面，再确认页面/iframe ready，随后才发送该模块内部命令。关闭命令则由宿主本地执行返回概览；如果动作已经成功，不应再让模型凭旧状态回答“无法关闭”。

驾驶舱的实时控制由受限工具 Schema 表达允许的导航目标和期次，Rust 发出 Tauri 事件，React 宿主切换路由并通过驾驶舱桥传入参数，页面结果再回传。英语学习复用实时会话的用户语音与页面消息桥，具备不同练习模块的业务路由。魔方和直播的宿主导航同样由 EasyInput 控制，子页面只接收列举的功能命令。

页面间消息不是可信的天然通道。桥接至少校验协议版本、准确 origin、窗口引用、随机 clientId/token 和命令类型；带 requestId 可去重。每个模块应只暴露它需要的能力，不要提供“执行任意脚本”一类泛化接口。

**常见竞态：** iframe 页面可能先发 `ready`，宿主监听器还没挂好，消息就丢了。魔方曾因此握手不成功，后续所有命令都被忽略。修复方法是让子页面重试 hello、宿主记录对端自己的 peer ID，并让容器可主动 ping 子页面重新上报 ready。设计桥时要考虑重试、幂等和超时，不要假定页面加载完成就等于业务 ready。

## 4. 直播：字幕和特效复用实时对话

### 4.1 业务路径

桌面嵌入模式中，开发板语音先走 EasyInput 实时会话。直播页只接收**用户最终转写**，用于画面字幕和贴纸/美颜命令；大模型回答不传入直播消息桥，因此不会显示在画面字幕。识别到“戴上面具”“加上胡子”“取消贴纸”“美颜八十”等表达后，直播页复用已有特效逻辑。

桌面模式不额外启动一套直播 ASR。独立网页模式仍保留原识别方式。直播预览/推流的电脑麦克风音轨与开发板的语音识别输入是两条用途不同的链路，不要混为一谈。

### 4.2 技术路径与边界

```text
开发板 PCM → EasyInput Rust 实时会话 → 用户最终转写事件
                                          ├→ 直播字幕
                                          └→ 受限命令 → 既有贴纸 / 美颜函数

模型回答 ──不进入──→ 直播字幕桥
电脑摄像头 / 麦克风 → 直播预览与 RTC 媒体轨道
```

直播 React 宿主通过受限 iframe 桥承载外部 Vue 页面。桌面嵌入服务使用明确的 embed 模式允许指定宿主来源；默认独立服务仍禁止任意网页嵌入。桥校验 parent origin、source、clientId 和 token；只发送允许的用户语音事件，不开放任意 Tauri 命令。

### 4.3 踩坑与验收

曾出现“说戴上面具没有调用贴纸”的用户反馈。排查不能只确认 ASR 有文字：还要逐段确认最终转写是否到达宿主、握手是否 ready、动作识别是否命中、命令是否被权限门控、页面既有贴纸函数是否真正执行。调试时用 requestId 和阶段事件区分“识别失败”“桥接失败”“动作映射失败”。

项目也遇到嵌入被 `X-Frame-Options: DENY` 阻止、RTC join 与 leave 竞争导致离页后连接又出现、中文美颜数值解析错误，以及 Token 不应进入 localStorage/观众链接等问题。RTC 离页要停止本地媒体并等待 join settled 再 leave；Token 应使用 Keychain；观众链接只含公开频道信息。

代码、构建和部分浏览器/WKWebView API 探测已完成，但这些不等于摄像头、开发板字幕、FaceUnity、声网双端直播已验收。相关实测项见 `docs/直播工作室与硬件语音集成.md`。

## 5. 麦当劳点餐：状态机和地址脱敏

### 5.1 业务路径

点餐不是让模型一次性生成完整订单，而是由模型按步骤调用高层 Function，客户端 Rust 状态机按当前会话状态校验并串行执行 MCP：查询地址、门店、菜单和详情，选餐、算价、再次确认，然后才允许创建订单。支付二维码由本机打开，支付必须由用户自己完成。

### 5.2 地址隐私处理

MCP 返回完整配送地址时，完整值只保留在客户端会话中用于最终履约；给模型的地址候选标签只包含区/县级区域，不播报小区、楼栋、楼层、房号、联系人和手机号。用户只需通过序号区分地址。日志也不应记录完整地址 ID、电话号码、支付 URL 或完整订单号。

这体现了“用途分离”：模型只拿到完成选择所需的最少信息，客户端在真正调用配送接口时使用本地保存的真实地址。不要试图仅靠提示模型“请保护隐私”；脱敏必须在 Rust 发送模型数据前执行。

### 5.3 防误下单和已踩坑

`create-order` 需要当前轮明确说“确认下单”，同时校验工具参数与真实 ASR 文本；报价过期需要重新算价和确认；每个会话防重复下单；支付不自动完成。MCP 字段有的按元、有的按分，格式化时不能共用同一转换逻辑。商品名相似不代表商品编码、价格或配送渠道一致；要记录渠道、门店、编码、各项费用。

生产 MCP 曾用于低金额真实创建订单并打开支付二维码的验证，但没有自动支付。后续实单仍应在创建前让用户核对金额、门店和地址。配置 Token 放 macOS Keychain，服务域名固定，不能由模型提供任意主机。

## 6. 三阶魔方：复用双模型页面和按钮

魔方模块默认隐藏。说“打开魔方”后宿主显示双盘页面；模块打开后，“同步重新打乱”触发页面右上角原有同步按钮；“一键完成七步”或“一起开始复原魔方”同时触发左右各自的一键按钮。语音层尽量复用已有按钮和求解流程，避免另写一套与页面状态不一致的控制逻辑。

魔方页面由本机服务提供，通过带随机 token 的双层消息桥控制。Jev 与 DeepSeek 各自保留模型和盘面状态；同步打乱使用共享公式，七步复原则分别由各自模型处理。魔方 API Key 存入 macOS Keychain，并通过本机受限桥回填；不进入实时语音消息、普通配置文件或诊断日志。

求解动作不能仅凭模型说“完成”就算成功。页面应检查候选步骤是否合法、状态版本是否匹配，以及最终状态是否达到 54/54 完成标准。Jev 曾发生“一键七步提前停止”；需要区分页面没有触发按钮、模型响应中断、候选非法被保护流程拒绝、以及模型有输出但盘面没有完成。项目采用本地模拟/安全候选与最终状态校验保护流程；网络失败和保护校验失败仍可能停止，需要按具体原因诊断。

语音同步按钮动作已实现并有编译验证；真实双盘状态变化及 Jev/DeepSeek 的在线模型七步复原仍需实际验收。参见 `docs/三阶魔方双模型与实时语音集成.md`。

## 7. 通用踩坑清单：小白排查顺序

| 看到的现象 | 常见根因 | 先查什么 |
|---|---|---|
| 唤醒词无反应 | 会话开关没传入 Rust；ASR 近音不在归一表；仍运行旧应用 | 会话启动诊断、最终转写原文、运行实例版本 |
| 说休息后还在回答 | 只挡下一轮，未取消当前 response；某条工具/本地动作路径绕过门控 | 检查 response cancel、Function Calling 与本地动作的共同入口 |
| 模块打开了却说找不到 | 导航成功但模型仍判断工具不可用；动作路由缺少宿主预过滤 | 打开模块命令是否本地消费并抑制错误模型回答 |
| iframe 已显示但命令没反应 | ready 丢失、clientId 校验错对象、origin/token 不一致 | 查看 hello/welcome/ready、peer ID、requestId 和精确来源 |
| 识别到命令但字幕/特效不工作 | 转写事件类型错误、桥消息漏发、动作映射或页面函数失败 | 沿 ASR → Rust → 宿主 → iframe → 页面函数分段打点 |
| 字幕出现模型回答 | 把所有语音事件都转给直播页 | 桥只允许用户最终转写事件，协议层不提供模型输出类型 |
| 驾驶舱关闭成功却播报失败 | 宿主已执行但模型又对同轮话语回答 | 把宿主关闭识别设为本地消费，并取消同轮模型回复 |
| 一键复原提前停止 | 把按钮触发等同于求解完成；忽略非法候选或输出截断 | 验证实际盘面、每步候选、终态，不只看按钮或模型文字 |
| 浏览器正常、桌面硬件不正常 | 浏览器不具备 USB、Keychain、麦克风权限或 Tauri IPC 环境 | 转到原生 Tauri + 真实开发板验收 |
| 新代码行为仍像旧版本 | 旧 bundle 与 tauri dev 同时运行；应用关闭只是隐藏 | Command+Q 完全退出后确认进程和版本，再启动当前源码 |

## 8. 推荐的验证分层

**第一层：纯逻辑验证。** 测试口令归一、命令匹配、地址脱敏、订单状态机、消息 Schema 和求解候选规则。这层快，适合先发现规则错误。

**第二层：构建与本地服务。** 前端构建、Rust 检查/测试、每个本地模块服务的 HTTP 健康检查和正确端口/路由。检查服务监听者属于哪个项目，HTTP 200 也要确认目标页面不是别的服务。

**第三层：Tauri 原生环境。** 验证 WebView iframe、Keychain、摄像头/麦克风权限、Tauri 事件、媒体 API 和签名 runner。浏览器预览不能证明这些能力。

**第四层：真实链路。** 接开发板确认 PCM/心跳、ASR 最终转写、休息/唤醒、语音工具调用与动作回执；直播确认摄像头、贴纸、字幕和声网第二设备观看；麦当劳确认真实 MCP 报价与人工确认；魔方确认两边按钮同时触发且两边盘面最终完成。

每一层都记录环境、输入、预期、实际、日志定位和是否真实外部副作用。服务启动成功不等于语音控制成功；编译成功不等于硬件链路验收成功。

## 9. 新手复现与代码导航

先从 `flow/plan.md` 看当前目标，再从 `flow/tasks/` 找对应任务卡。遇到需求变化时先把用户语言转成清晰的输入、状态、动作和反馈，然后查对应模块实现文档。调试时保留原始最终转写和会话 ID，按“识别 → 门控/路由 → IPC/消息桥 → 页面动作 → 回执”逐段定位。

主要入口：实时语音与唤醒门控在 `src-tauri/src/realtime.rs`、`src-tauri/src/speech.rs` 和 `src/pages/RealtimeCallPage.tsx`；驾驶舱在 `src/pages/CockpitPage.tsx`、`src/cockpit.ts`；直播在 `src/pages/LivePage.tsx`、`src/live.ts` 与 `src-tauri/src/live.rs`；麦当劳在 `src-tauri/src/mcd_order.rs`、`src-tauri/src/mcd_mcp.rs`；魔方在 `src/pages/CubePage.tsx`、`src/cube.ts`。具体协议和最新验收边界以同目录模块说明为准。

## 10. 术语表

**ASR：** 自动语音识别，把音频转换成文字。**最终转写：** 识别完成后可用于执行的稳定文本，不是中间猜测。**Function Calling：** 模型用结构化参数请求客户端执行一个已定义工具。**PCM：** 未压缩的数字音频采样。**Tauri IPC：** 前端调用 Rust 本地能力或接收事件的通道。**iframe：** 页面里嵌入的另一个网页。**消息桥：** 两个页面之间受协议和来源校验的消息通道。**Keychain：** macOS 系统密钥存储，用于保存 API Key 等敏感值。**RTC：** 实时音视频通信。**MCP：** 模型上下文协议；本项目将其用于受控访问麦当劳点餐服务。

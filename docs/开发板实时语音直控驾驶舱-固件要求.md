# 开发板实时语音直控驾驶舱：固件要求

## 结论

**驾驶舱控制不需要新增或修改固件业务协议。** 模块识别、豆包 Function Calling、EasyInput 页面切换和执行结果回传全部由 Mac 客户端完成。固件不需要知道“驾驶舱”“作业分析”或 `cockpit_navigate`，也不保存模块列表。

如果当前固件已经完整实现下列实时通话要求，可以保持当前版本，只做实板复验；任何一项不满足时，才需要在固件项目中修正对应能力。

## 固件项目执行清单

### 1. 实时通话触发

- 实时通话键按下时发送一次触发，客户端只消费按下沿并负责去重。
- 推荐发送 Hotkey App Command `EasyInputRealtime`；兼容方案是标准键盘报告 `Ctrl+Shift+R`。
- 不要在固件中把语音命令转换成驾驶舱模块 ID。

### 2. 设备发现和控制确认

- 就绪后每约 1 秒发送一个 `EIHB` v1 心跳。
- 收到 `EICC Start` 后清理旧会话缓冲并返回匹配 `session_id + sequence` 的 `EICA`。
- 正确处理并确认 `EICC Keepalive`、`EICC Stop`；Stop 后立即停止旧会话采集和播放。
- Start ACK 需要在 3 秒内返回，`status=0` 表示成功。

### 3. 麦克风上行

- 使用 `EIAU` v2。
- 16 kHz、单声道、PCM S16LE。
- 每帧 20 ms，即 320 samples / 640 bytes PCM；连同 32-byte 头共 672 bytes。
- `sequence` 每帧递增，`session_id` 必须等于本次 Start。
- 不设置固定 5 分钟采集上限；仅在 Stop、不可恢复错误或明确安全看门狗超时时停止。

### 4. 扬声器下行

- 接收 `EISP` v1。
- 24 kHz、单声道、PCM S16LE。
- 每帧 20 ms，即 480 samples / 960 bytes PCM；连同 32-byte 头共 992 bytes。
- 只播放当前活动 session；丢弃重复、旧 session 和明显过期的 sequence。
- Stop 或新 Start 到达时清空旧播放缓冲，避免上一轮声音串入下一轮。

### 5. 全双工质量

- 建议使用扬声器参考信号做 AEC；至少要通过结构、增益和有界抖动缓冲降低回声。
- 建议记录上行丢帧、下行乱序、播放欠载、I2S 错误和当前 session，便于对照 EasyInput JSONL 诊断日志。

## 固件不需要做的事情

- 不解析豆包 WebSocket、ASR 文本或 Function Calling。
- 不实现 `cockpit_navigate`。
- 不保存驾驶舱页面、模块别名、期次或模糊匹配规则。
- 不修改现有 2,048-byte USB 配置协议来传输驾驶舱命令。
- 不接触豆包 API Key、驾驶舱地址或网页消息。

## 建议实板验收

1. 启动 EasyInput Tauri 应用，保持训练营驾驶舱地址可访问。
2. 按开发板实时通话键，确认客户端进入“通话”且收到 Start ACK。
3. 依次说：“打开驾驶舱”“打开作业分析”“切换到学员画像”“查看第五期”。
4. 每条指令应使 EasyInput 自动进入驾驶舱并切换到对应页面；豆包应在驾驶舱返回成功后再播报结果。
5. 说“打开作业还是学员”，应先询问目标，不应擅自切换。
6. 连续通话超过 5 分钟，确认上行音频不断流；播放期间确认没有明显自激回声。
7. 导出 EasyInput 实时语音诊断日志，检查 `function_call.received`、`cockpit_tool.execution_started`、`cockpit_tool.execution_succeeded`；失败时检查 `cockpit_tool.execution_failed`。

## 请从固件项目带回的信息

- 固件版本号和对应提交 ID。
- 触发方式：`EasyInputRealtime` 或 `Ctrl+Shift+R`。
- `EIHB/EICC/EICA/EIAU/EISP` 各协议版本。
- 是否存在固定采集时长限制、AEC 是否启用。
- 一次完整验收的串口日志，以及丢帧、乱序、欠载和 I2S 错误计数。
